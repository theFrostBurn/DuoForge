# DuoForge 구현 계획

기준 문서는 `require/PRD.md` v1.5이다. 구현은 안전 게이트가 선행되는 수직 슬라이스로 진행한다.

1. PowerShell 7 네이티브 CLI와 인수 없는 홈 메뉴
2. 메뉴와 명시적 명령이 공유하는 요청·검증 계층
3. 구독 인증 진단과 API 자격증명 우선 조건의 실패 폐쇄
4. Windows 경로 정규화, 동일·중첩·출력 경계 검사
5. Markdown 인벤토리, UTF-8 검증, 용량 제한과 불변 스냅샷
6. 실행 ID, 매니페스트, 원자적 상태 저장, 이벤트 로그와 쟁점 원장
7. 공급자별 최악 호출 수를 계산하는 실행 계획기

31. 사용자 결정별 최신 답변 집계, 영향 단계 감사 보존과 과거 질문의 결정론적 확정 처리

## 안전 결정

- 실제 모델 호출은 실행 계획에 대한 사용자의 명시적 확인 전에는 수행하지 않는다.
- 모델과 추론 정도는 공급자별로 매 실행에서 명시적으로 선택하며, 누락된 요청·매니페스트는 실패 폐쇄한다.
- 권장값은 현재 CLI 목록에 존재할 때 Codex `gpt-5.6-sol + high`, Claude `opus + high`다. 값이 사라지면 Codex `isDefault`·기본 effort 또는 Claude `default`·현재 지원 effort로 이동하며, 어떤 권장 표시에서도 사용자가 번호를 직접 선택해야 한다.
- 인증 상태 명령의 원문은 저장하지 않는다. 공개 가능한 인증 유형, 종료 코드와 검사 시각만 정규화한다.
- API 자격증명 환경 변수는 이름과 존재 여부만 다루며 값을 출력하거나 저장하지 않는다.
- 현재 Codex Windows `read-only` 격리 후보는 쓰기는 차단하지만 범위 밖 읽기와 자식 프로세스를 허용한다. 세 계약을 모두 만족하는 별도 OS 격리 또는 무도구 표면을 증명하기 전까지 `dual-project-audit`는 기능 플래그로 비활성화한다.
- 문서 모드도 원본을 모델 작업 폴더로 열지 않고 스냅샷 내용만 전달하는 구조를 사용한다.
- 공급자 실패의 stdout·stderr 원문은 저장하지 않고 오류 범주, 공개 오류 코드와 재시도 가능 여부만 기록한다.
- 사용자 일시정지는 실행 중인 호출을 강제 종료하지 않고 완료된 산출물을 커밋한 다음 다음 호출 전에 적용한다.
- 추가 근거는 실행 결과 폴더 밖의 UTF-8 Markdown만 허용하고 원본 해시와 동일한 불변 스냅샷으로 복사한다.

## Core Beta 안정화 완료 범위

1. 안내형 인증 실패 행렬과 메뉴·CLI 동등성
2. 전용 형식 복구와 손상 산출물 복구
3. 최대 3개 질문 카드 배치와 강화된 결정 정보
4. 결정 변경·자유 제약·3라운드 확장과 결정 반영 재최종화
5. 대용량 문맥 배치·커버리지·부분 완료와 90분 누적 상한
6. 공동 문서 13단계와 독립 문서 12단계 실제 구독 E2E

## 별도 승인 또는 선행 안전 게이트 현황

1. 3A OS 격리 스파이크: 실행 완료. 쓰기 차단과 원본 SHA-256 동일은 통과했지만 범위 밖 읽기·자식 프로세스 차단이 실패했다.
2. 3A Beta 구현·활성화: 스파이크 실패에 따라 착수하지 않으며 `DF-PREFLIGHT-3A-ISOLATION` 게이트를 유지한다.

## 2026-07-28 구현 결과

- PowerShell 모듈 버전: `0.8.0`
- 현재 확인 CLI: Codex `0.145.0`, Claude Code `2.1.220`
- 현재 Codex 기능 검사: `--model`, `--config`, `--ignore-user-config`, `--ignore-rules`, `read-only`, 임시 세션, JSONL 이벤트와 출력 스키마 확인
- 현재 Claude 기능 검사: `--model`, `--effort`, `--safe-mode`, 빈 도구 목록, 엄격한 MCP 설정, Chrome 차단, 세션 비보존과 JSON 스키마 확인
- 오프라인 회귀 테스트: 52개 통과
- CLI 스모크: `help`, 개인정보 제거 `doctor --json`, 명시적 모델·추론 정도를 포함한 `shared-document --plan-only` 통과
- `--plan-only`에서 결과 폴더나 확정 실행이 생성되지 않음을 확인
- 공급자별 라이브 스모크: `gpt-5.6-sol/high`, `Opus 5(opus)/high` 구조화 초안 성공, 금지 도구 이벤트 0건, 임시 원문 파일 0개와 구독 인증 유지 확인
- 라이브 안정화: `codex.ps1` 대신 종료 코드를 보존하는 실행형 래퍼 우선, 승인 환경의 `Path` 복사, Codex 엄격 JSON Schema 호환 타입을 반영
- 전체 E2E: `run-20260727-142702-0eeb82`에서 2라운드 13/13 단계 커밋, 라운드 장벽·상호 비평·응답·교대 합성·최종 검증과 최종 파일 5개 생성 확인
- E2E 복구: 비밀 제거 후 배열 재정규화 결함을 수정하고 같은 실행을 `RESUMABLE_ERROR`에서 재개해 완료
- 독립 문서 전체 E2E: `run-20260727-155148-7617d3`에서 `gpt-5.6-sol/high`, `opus/high`로 2라운드 12/12 단계와 최종 파일 6개를 커밋하고 사용자 결정 8개 반영 후 `COMPLETED` 확인
- 독립 문서 안전 결과: 원본 2개 SHA-256 동일, 금지 도구 이벤트 0건, 공급자 작업 파일 0개, 미해결 질문 0개, 호출 후 두 구독 인증 유지
- 독립 문서 복구 검증: Codex 엄격 스키마의 선택 속성 문제를 필수 속성 계약으로 수정해 같은 실행을 재개했고, 다중 결정 최신값 집계·반복 무효화 감사 이력·과거 질문 재등장 결함을 수정해 추가 전체 재실행 없이 최종화
- 누적 라이브 모델 실행 시간: 결정 반영 재실행을 포함해 약 35분 21초로 90분 상한 이내
- 3A 격리 스파이크: Windows 읽기 전용 샌드박스가 파일 쓰기는 거부했지만 범위 밖 읽기와 중첩 자식 프로세스 실행을 허용하여 활성화 게이트 실패
- 모델 카탈로그 갱신: Codex 계정별 `model/list`와 Claude CLI 별칭·effort를 프로세스마다 다시 읽고, 사라진 모델이나 effort에 권장이 남지 않는 회귀 테스트 추가

두 문서 모드의 구조화 단계 실행, 재개, 최종 문서 렌더링, 사용자 결정·추가 근거에 따른 선택 재실행, 쟁점 설명, 대용량 입력, 안전한 일시정지와 구독 한도 복구를 포함한 Core Beta 후보가 구현되었다. 라이브 공급자 어댑터는 공급자별 스모크와 공동·독립 문서 2라운드 전체 단계 E2E를 모두 통과했다. `dual-project-audit`는 [3A 격리 스파이크](3A_ISOLATION_SPIKE.md)의 실패 판정에 따라 계속 비활성 상태다.
