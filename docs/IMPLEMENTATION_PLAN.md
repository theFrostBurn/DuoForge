# DuoForge 구현 계획

기준 문서는 `require/PRD.md` v1.4이다. 구현은 안전 게이트가 선행되는 수직 슬라이스로 진행한다.

## 현재 구현 슬라이스

1. PowerShell 7 네이티브 CLI와 인수 없는 홈 메뉴
2. 메뉴와 명시적 명령이 공유하는 요청·검증 계층
3. 구독 인증 진단과 API 자격증명 우선 조건의 실패 폐쇄
4. Windows 경로 정규화, 동일·중첩·출력 경계 검사
5. Markdown 인벤토리, UTF-8 검증, 용량 제한과 불변 스냅샷
6. 실행 ID, 매니페스트, 원자적 상태 저장, 이벤트 로그와 쟁점 원장
7. 공급자별 최악 호출 수를 계산하는 실행 계획기
8. 오프라인 가짜 공급자로 검증하는 라운드 장벽·재개 코어
9. 단계별 JSON Schema, 스냅샷 전용 프롬프트와 공급자 원문 비저장·비밀값 제거
10. Codex/Claude 문서 모드 어댑터, 격리 작업 폴더와 환경 변수 허용 목록
11. 공동 문서·독립 문서 최종 산출물과 쟁점·채택 기록 렌더러
12. `resume --live` 명시 동의 게이트와 `issues` 조회
13. 사용자 질문 카드, 답변·보류 기록과 마지막 합성/검증 단계의 선택적 무효화
14. 상태 기반 메뉴의 실행 선택, 질문 응답, 라이브 재개와 결과 폴더 열기
15. Codex·Claude별 필수 모델·추론 정도 선택, 매니페스트 고정과 실제 CLI 인수 전달

## 안전 결정

- 실제 모델 호출은 실행 계획에 대한 사용자의 명시적 확인 전에는 수행하지 않는다.
- 모델과 추론 정도는 공급자별로 매 실행에서 명시적으로 선택하며, 누락된 요청·매니페스트는 실패 폐쇄한다.
- 인증 상태 명령의 원문은 저장하지 않는다. 공개 가능한 인증 유형, 종료 코드와 검사 시각만 정규화한다.
- API 자격증명 환경 변수는 이름과 존재 여부만 다루며 값을 출력하거나 저장하지 않는다.
- 현재 Codex `read-only`는 명령 도구를 제거하지 않는다. 별도의 OS 격리 또는 무도구 표면을 증명하기 전까지 `dual-project-audit`는 기능 플래그로 비활성화한다.
- 문서 모드도 원본을 모델 작업 폴더로 열지 않고 스냅샷 내용만 전달하는 구조를 사용한다.

## 2026-07-27 구현 결과

- PowerShell 모듈 버전: `0.3.0`
- 현재 확인 CLI: Codex `0.145.0`, Claude Code `2.1.220`
- 현재 Codex 기능 검사: `--model`, `--config`, `--ignore-user-config`, `--ignore-rules`, `read-only`, 임시 세션, JSONL 이벤트와 출력 스키마 확인
- 현재 Claude 기능 검사: `--model`, `--effort`, `--safe-mode`, 빈 도구 목록, 엄격한 MCP 설정, Chrome 차단, 세션 비보존과 JSON 스키마 확인
- 오프라인 회귀 테스트: 24개 통과
- CLI 스모크: `help`, 개인정보 제거 `doctor --json`, 명시적 모델·추론 정도를 포함한 `shared-document --plan-only` 통과
- `--plan-only`에서 결과 폴더나 확정 실행이 생성되지 않음을 확인

현재 완료된 것은 두 문서 모드의 구조화 단계 실행, 재개, 최종 문서 렌더링, 사용자 결정에 따른 마지막 단계 선택 재실행까지 포함한 Core Beta 골격이다. 라이브 공급자 어댑터는 코드와 명령 계약까지만 연결했으며 실제 모델 호출 E2E는 수행하지 않았다. 쟁점 설명 호출과 구독 한도 복구는 다음 슬라이스이고, `dual-project-audit`는 계속 비활성 상태다.

## 완료 게이트

- 오프라인 P0 회귀 테스트 통과
- PowerShell 7, 한글·공백 경로 스모크 테스트 통과
- 실제 공급자 E2E는 별도 사용자 동의 후 실행
- 3A는 무도구 또는 OS 격리, 원본 전후 SHA-256 동일성과 도구 이벤트 0건이 모두 증명되어야 활성화
