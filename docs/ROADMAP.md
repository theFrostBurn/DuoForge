# DuoForge 개선 로드맵

이 문서는 **사용자와 방향을 합의한 작업의 현재 상태**와 **PRD에만 등록된 장기 검토 후보**를 구분하는 단일 인덱스다. 실제 지원 동작은 `README.md`, 현재 제품 계약은 `require/PRD.md`, 구현을 마친 슬라이스와 안전 게이트는 `docs/IMPLEMENTATION_PLAN.md`가 권위 문서다.

상태는 다음 의미로만 사용한다.

- `완료`: 구현과 회귀 검증을 마친 현재 기준선
- `계획됨`: 사용자와 다음 구현 범위·순서를 합의한 항목
- `후속 후보`: 방향은 논의했지만 선행 작업의 사용 결과를 본 뒤 구현 여부를 정할 항목
- `장기 후보`: PRD에 검토 대상으로 등록됐으나 우선순위와 상세 범위를 합의하지 않은 항목
- `게이트됨`: 안전 선행 조건이 충족되기 전에는 구현 또는 활성화하지 않을 항목

새 아이디어는 근거와 우선순위가 합의되기 전까지 `계획됨`으로 올리지 않는다. 운영 유지보수 과제와 구현 방식의 추측도 제품 로드맵 항목으로 부풀리지 않는다.

## 1. 이번에 완료한 작업

### TUI 토론 관전 피드 1차 — 완료

고정형 진행판이 장벽과 현재 작업에 더해 검증된 최근 확정 결과 최대 3건을 이어서 보여주도록 표시 계층을 개선했다. 공급자 실행 계약은 바꾸지 않았다.

구현 결과:

1. 해시와 단계 결과 스키마 검증을 통과한 `COMMITTED` 산출물 중 최근 최대 3건을 단계 그래프 순서대로 표시한다.
2. 각 항목은 공급자, 라운드, 단계, 기록된 대상 문서 A/B·공동·합의 문서와 현재 공개 가능한 정제 요약을 사용한다. workflow-v1에 기록되지 않은 문서 계보는 추정하지 않는다.
3. 영문 축약 `C/M/m` 대신 다음 의미를 구분한 자연어 행동 집계를 표시한다. 0건 항목은 폭을 아끼기 위해 생략한다.
   - 새 쟁점: 치명적·주요·경미한 지적
   - 검토 응답: 수용·부분 수용·거부·보류·근거 필요·사용자 결정
   - 실제 편집 반영: 반영·부분 반영·미반영·보류
4. 응답 수용과 실제 문서 반영을 합치거나 `합의`로 과장하지 않는다.
5. 최소 `72×20`에서는 기존 최근 확정 영역을 항목당 최대 두 줄의 피드로 교체한다. 현재 작업, 최소 장벽 3개와 하단 상태를 밀어내지 않으며 넓은 화면에서도 같은 정보 순서를 유지한다.
6. ANSI 없는 누적 로그는 기존 최신 확정 동작을 유지하고 같은 항목을 heartbeat마다 중복 출력하지 않는다.

이번 범위에서 바꾸지 않는 것:

- 공급자 호출 수·순서, 프롬프트, 단계 의존성, 저장·재개 스키마와 이벤트 허용 목록
- `issueKey` 연결, 대표 쟁점 선정과 주장·근거·응답 이유 본문 공개
- 원시 stdout·stderr, 생성 중 텍스트, 문서·컨텍스트 본문과 내부 사고 과정
- `context-batch-analysis`의 일반화된 안전 요약

검증 결과:

- 0·1·2·3건과 4건 이상에서 마지막 3건의 선택·순서가 결정론적이다.
- 최신 또는 중간 산출물의 해시·스키마가 손상되면 해당 항목만 제외하고 유효한 최근 항목으로 채운다.
- 모든 응답·반영 상태가 의미가 섞이지 않는 한국어 문구로 집계되고 0건 생략이 일관된다.
- `72×20`과 넓은 화면에서 줄 수·표시 폭·한글·emoji·제어문자 경계가 보존된다.
- workflow-v1 읽기 호환, 문맥 배치 원요약 비노출, 대상 문서 표시와 누적 로그 폴백이 회귀하지 않는다.
- PowerShell 7 전체 오프라인 회귀 `102개 통과, 0개 실패`와 `git diff --check` 통과를 확인했다. `git status --short`에는 구현·테스트·README·PRD·ROADMAP 5개 변경만 남았고 실제 공급자 호출은 수행하지 않았다.

## 6. 명시적 비목표

- 원시 공급자 출력, 생성 중 토큰이나 내부 사고 과정의 실시간 중계
- 분모와 상태 의미를 먼저 합의하지 않은 단순 `합의율`
- 정보 전달 효과 없이 애니메이션 자체를 위한 화면 효과
- 장기 후보를 별도 범위 승인 없이 현재 지원 기능처럼 문서화하는 것

## 다음 구체화 순서

1. 1차 확정 피드를 실제 사용한 뒤에도 관전감이 부족한지 확인하고 `issueKey` 미니 스레드의 필요성과 공개 계약을 판단한다.
2. 더 넓은 시각화가 필요할 때 읽기 전용 토론 흐름과 웹·데스크톱 UI를 별도 설계한다.
3. PRD 유래 장기 후보는 사용자가 우선순위를 정한 항목만 별도 PRD·구현 슬라이스로 승격한다.
4. 쓰기 또는 범위 밖 접근이 가능한 확장은 격리 게이트가 해소되기 전에는 활성화하지 않는다.
