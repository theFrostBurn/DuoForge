# DuoForge 장기 개선 로드맵

이 문서는 현재 구현 범위를 넘어서는 대규모 개선·확장 후보의 단일 인덱스다. 현재 제품 계약은 `require/PRD.md`, 승인된 구현 순서와 완료 상태는 `docs/IMPLEMENTATION_PLAN.md`, 실제 지원 동작은 `README.md`가 권위 문서다. 여기의 후보는 별도 승인과 필요한 경우 별도 PRD 없이는 구현 약속이 아니다.

상태는 `완료`, `계획됨`, `후보`, `게이트됨`으로 구분한다.

| 영역 | 상태 | 후보 결과 | 주요 선행 조건 |
|---|---|---|---|
| 의미 기반 대용량 문맥 1차 | 완료 | 구조 기반 분할, 위치 지도, 추출형 앞뒤 브리지, 균형 부분 커버리지 | `docs/IMPLEMENTATION_PLAN.md` 슬라이스 9, 오프라인 회귀 96개 |
| 계층형 문서 이해 2차 | 후보 | 모델 보조 전체 지도와 검증 가능한 구간 요약 | 1차 의미 배치 완료, 추가 호출·동의·예산 계약 |
| A/B 의미 대응 | 후보 | 제목 순서가 달라도 관련 섹션을 연결하는 교차 참조 그래프 | 안정적인 섹션 ID, 근거 위치 계약 |
| 계층형 토론 | 후보 | 배치별 이중 검토·교차 비평·잠정 합의 뒤 전체 일관성 검증 | 호출 상한 재설계, 새 단계·결과·재개 버전 계약 |
| 대규모 입력 처리 엔진 | 후보 | 스트리밍 인벤토리, 증분 해시, 실제 토큰·시간·사용량 기반 재계획 | 의미 배치와 커버리지 계약 안정화 |

| 공급자 호환성 자동 검증 | 후보 | CLI 버전·인증·모델·기능 변화에 대한 능력 매니페스트와 회귀 행렬 | 현재 인증·비노출 계약 유지 |
| 모드 4 격리 기반 | 게이트됨 | 범위 밖 읽기·자식 프로세스·쓰기의 선제 차단과 OS 수준 증명 | `docs/3A_ISOLATION_SPIKE.md`의 실패 게이트 해소 |
| 모드 3B 패치·diff 제안 | 후보 | 적용하지 않는 승인 가능 패치 제안 | 문서 계보·근거·승인 계약 안정화 |
| 모드 3C 격리 적용 | 게이트됨 | 격리 브랜치에서 코드 적용·빌드·테스트 | 모드 4 수준 격리 증명, 별도 쓰기 승인 흐름 |
| 웹·데스크톱 UI | 후보 | 실행 계획·진행·결정·재개를 제공하는 사용자 UI | 상태·이벤트 공개 계약 안정화 |

## 다음 구체화 순서

1. 실제 대용량 fixture의 품질과 호출 계획을 평가한 뒤 계층형 문서 이해, A/B 의미 대응과 계층형 토론을 각각 별도 설계한다.
2. 쓰기 또는 범위 밖 접근이 가능한 확장은 모드 4 격리 게이트가 해소되기 전에는 활성화하지 않는다.
3. 각 후보가 구현 대상으로 승인되면 PRD 요구사항, 저장·재개 버전, 호출·보안 예산과 완료 증거를 먼저 확정한다.
