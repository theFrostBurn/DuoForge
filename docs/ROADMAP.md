# DuoForge 개선 로드맵

이 문서는 **사용자와 방향을 합의한 작업의 현재 상태**와 **PRD에만 등록된 장기 검토 후보**를 구분하는 단일 인덱스다. 실제 지원 동작은 `README.md`, 현재 제품 계약은 `require/PRD.md`, 구현을 마친 슬라이스와 안전 게이트는 `docs/IMPLEMENTATION_PLAN.md`가 권위 문서다.

상태는 다음 의미로만 사용한다.

- `완료`: 구현과 회귀 검증을 마친 현재 기준선
- `계획됨`: 사용자와 다음 구현 범위·순서를 합의한 항목
- `후속 후보`: 방향은 논의했지만 선행 작업의 사용 결과를 본 뒤 구현 여부를 정할 항목
- `장기 후보`: PRD에 검토 대상으로 등록됐으나 우선순위와 상세 범위를 합의하지 않은 항목
- `게이트됨`: 안전 선행 조건이 충족되기 전에는 구현 또는 활성화하지 않을 항목

새 아이디어는 근거와 우선순위가 합의되기 전까지 `계획됨`으로 올리지 않는다. 운영 유지보수 과제와 구현 방식의 추측도 제품 로드맵 항목으로 부풀리지 않는다.

## 1. 이번에 완료한 작업

### 실행별 안전 진단과 지원 상관관계 — 완료

오류가 있는 실행은 run의 `diagnostics.jsonl`에 안전한 허용 목록 레코드를 append하고, run 부재·쓰기 실패 시 local 진단 디렉터리로 폴백한다. 단계·공급자/process·중단 복구·최종 renderer 오류의 `diagnosticId`를 단계 상태, 이벤트, observer와 반환 결과에 연결했으며 모든 사용자 표면이 같은 DF 코드와 writer의 실제 최종 경로를 표시한다.

구현 결과:

1. 정상 실행에는 빈 진단 파일이나 미사용 `logs\`를 만들지 않는다. 기존 실행·fixture의 `logs\`는 삭제·재작성하지 않는다.
2. writer 이중 실패는 원래 오류를 가리지 않고 `DF-DIAGNOSTIC-WRITE` 경고만 남긴다.
3. 원문 stdout·stderr, 프롬프트·문서·컨텍스트·모델 결과, 명령·환경·인증 값, 절대 입력 경로와 원시 예외 데이터는 진단·이벤트·화면에 기록하지 않는다.
4. 무인자 홈 메뉴·엔트리포인트, run/local 폴백, process 메타데이터, 다중 재시도, interrupted recovery, renderer, 고정형·누적 UI, 메뉴·CLI와 보안 canary를 PowerShell 7 오프라인 회귀로 고정했다.
5. `118개 통과, 0개 실패`, 변경 PowerShell parser 검사, 생성된 모든 진단 행의 `ConvertFrom-Json -Depth 100` 재파싱을 완료했다. 실제 공급자 호출은 수행하지 않았다.

### 대화형 메뉴와 LIVE 읽기 경험 2차 — 완료

번호를 읽고 입력하던 메뉴를 커서 이동·`Enter` 중심의 공통 선택기로 통합하고, 기존 heartbeat를 사용한 LIVE 스피너와 높이별 최근 완료 개요·단일 상세 스크롤을 추가했다. 내부 실행·저장 계약은 바꾸지 않았다.

구현 결과:

1. `↑/↓` 순환, `Home/End`, `Enter`, `Esc`, 숫자·영문 단축키와 비활성 이유를 모든 주요 메뉴에서 일관되게 제공한다. 권장 모델·분석 깊이는 사용자 확정 전에는 선택값이 아니다.
2. VT가 없으면 Windows 콘솔 커서 API로 같은 방향키 메뉴를 유지한다. 두 커서 렌더링 방식이나 키 읽기가 실패할 때만 ANSI 없는 줄 입력으로 한 번 폴백하고, 비대화형 환경은 입력을 기다리지 않는다.
3. 스피너는 기존 `PROVIDER_TICK`의 초 값으로만 움직이며 별도 타이머·I/O·호출·가짜 진행률을 추가하지 않는다.
4. 최근 완료는 높이에 따라 1·2·최대 3건을 공백 우선 여러 줄로 펼친다. 상세는 선택한 한 건만 `PgUp/PgDn/Home/End`로 읽고 `Esc`로 돌아간다.
5. 화면만 `분석 깊이`, `새 항목`, `의견 처리`, `문서 반영` 같은 일상어를 사용한다. 내부 ID·스키마·JSON은 유지하고 알 수 없는 값은 원래 값으로 폴백한다.
6. 질문은 현재 상태·핵심 쟁점·AI 처리·사용자 요청 종류와 목적·각 선택 결과를 순서대로 보여준다. 기본 카드는 남는 높이를 핵심 쟁점·제안·요청에 우선 배분하고, 안전한 전체 보기에서는 긴 구조화 필드를 생략 없이 터미널 스크롤로 읽고 결정 화면으로 돌아온다. 문서는 문서 A/문서 B/최종 문서, 선택지는 1안/2안/3안, AI는 Codex/Claude로 표기를 분리하며 기존 A/B 결정 코드는 호환 경계 안에만 남긴다. 객관식과 같은 첫 화면의 `[O]`에서 선택지 밖 의견을 현재 질문의 주관식 답변 또는 여러 질문의 공통 전제로 구분해 입력할 수 있다. 전자는 질문을 완료하고 후자는 질문을 남긴 채 모든 답변과 함께 양쪽 최종 단계에 적용한다. 답변 뒤에는 다음 미답변 질문으로 이어지고, 일시정지 상태에서도 남은 질문 수와 재진입 동작을 유지하며 모두 답하기 전에는 작업 재개를 막는다. 이전 답변을 바꿀 때는 목록부터 대상 문서·질문 제목·현재 답변을 보여주고, 새 선택 전에 원래 질문·핵심 쟁점·현재 답변을 다시 표시한다. 신규 기록에는 질문 제목·문장을 보존하고 기존 기록은 복원 표시를 붙인다.
7. 한 관문의 모든 답변을 최종 문서·검증에 반영한 뒤 새 결정이 있을 때만 다음 질문 관문을 연다. 최초 관문을 포함해 최대 3회로 제한하고 `1/3`~`3/3`을 표시하며, 일찍 해소되면 즉시 완료한다. 세 번째 검토 뒤에도 남은 새 질문은 `QUESTION_LIMIT_REACHED`로 보존하고 완료로 오인시키지 않는다.
8. 네 지원 프레임의 폭·높이와 가독성, 정확한 확인 토큰, 원문 비노출과 기존 `P` 안전 일시정지를 PowerShell 7 오프라인 회귀 `124개 통과, 0개 실패`로 고정했다. 실제 공급자 호출과 `resume --live`는 수행하지 않았다.

### TUI 토론 관전 피드 1차 — 완료

고정형 진행판이 장벽과 현재 작업에 더해 검증된 최근 확정 결과 최대 3건을 이어서 보여주도록 표시 계층을 개선했다. 공급자 실행 계약은 바꾸지 않았다. 이 항목은 역사적 1차 기준선이며 현재 화면 동작은 위 2차 구현이 대체한다.

구현 결과:

1. 해시와 단계 결과 스키마 검증을 통과한 `COMMITTED` 산출물 중 최근 최대 3건을 단계 그래프 순서대로 표시한다.
2. 각 항목은 공급자, 라운드, 단계, 기록된 대상 문서 A/B·공동·합의 문서와 현재 공개 가능한 정제 요약을 사용한다. workflow-v1에 기록되지 않은 문서 계보는 추정하지 않는다.
3. 영문 축약 `C/M/m` 대신 다음 의미를 구분한 자연어 행동 집계를 표시한다. 0건 항목은 폭을 아끼기 위해 생략한다.
   - 새 쟁점: 치명적·주요·경미한 지적
   - 검토 응답: 수용·부분 수용·거부·보류·근거 필요·사용자 결정
   - 실제 편집 반영: 반영·부분 반영·미반영·보류
4. 응답 수용과 실제 문서 반영을 합치거나 `합의`로 과장하지 않는다.
5. 최소 `72×20`에서는 기존 최근 확정 영역을 항목당 최대 두 줄의 피드로 교체한다. 현재 작업, 최소 장벽 3개와 하단 상태를 밀어내지 않으며 넓은 화면에서도 같은 정보 순서를 유지한다.
6. ANSI 없는 누적 로그는 기존 최신 확정 동작을 유지하고 같은 항목을 heartbeat마다 중복 출력하지 않는다.

이번 범위에서 바꾸지 않는 것:

- 공급자 호출 수·순서, 프롬프트, 단계 의존성, 저장·재개 스키마와 이벤트 허용 목록
- `issueKey` 연결, 대표 쟁점 선정과 주장·근거·응답 이유 본문 공개
- 원시 stdout·stderr, 생성 중 텍스트, 문서·컨텍스트 본문과 내부 사고 과정
- `context-batch-analysis`의 일반화된 안전 요약

검증 결과:

- 0·1·2·3건과 4건 이상에서 마지막 3건의 선택·순서가 결정론적이다.
- 최신 또는 중간 산출물의 해시·스키마가 손상되면 해당 항목만 제외하고 유효한 최근 항목으로 채운다.
- 모든 응답·반영 상태가 의미가 섞이지 않는 한국어 문구로 집계되고 0건 생략이 일관된다.
- `72×20`과 넓은 화면에서 줄 수·표시 폭·한글·emoji·제어문자 경계가 보존된다.
- workflow-v1 읽기 호환, 문맥 배치 원요약 비노출, 대상 문서 표시와 누적 로그 폴백이 회귀하지 않는다.
- PowerShell 7 전체 오프라인 회귀 `102개 통과, 0개 실패`와 `git diff --check` 통과를 확인했으며 커밋 `6bf68ee`에 반영했다. 실제 공급자 호출은 수행하지 않았다.

### 모든 사람용 터미널 출력 문법 — 완료

기존 질문·메뉴·CLI·LIVE·오류 화면에 공통 page/section/field/list/notice renderer를 적용한다. 섹션 표식과 높이별 여백, `WindowWidth - 1` 폭 인식 줄바꿈, hanging indent, ASCII·무색 폴백을 추가하되 정확한 확인 토큰과 비대화형 무대기, JSON·저장 스키마와 공급자 비노출 경계는 유지한다.

구현 순서:

1. D-039형 질문 카드·전체 보기와 이전 답변 변경 화면을 파일럿으로 고정한다.
2. 메뉴와 대화형 작업 화면, CLI 보고서, LIVE 진행판·누적 로그, 오류·진단·도움말 순으로 이전한다.
3. 네 지원 프레임과 ASCII·무색 fixture, 추적 PowerShell 파서·오프라인 전체 회귀·직접 출력 전수 감사를 완료한다.

완료 결과:

- D-039형 질문 화면에서 시작해 메뉴 → 대화형 작업 화면 → CLI 보고서 → LIVE 진행판·로그 → 오류·도움말 순서로 공통 renderer를 적용했다.
- `72×20`, `80×24`, `100×30`, `120×32` 합성 질문·LIVE 화면의 폭·높이와 가독성, 48~120열 renderer의 hanging indent·문단·ASCII 무색 폴백을 고정했다.
- D-040형 긴 질문은 120×32와 160×40에서 핵심 쟁점·제안 방향을 자르지 않고 제목·본문·하위 제안을 분리하며, 남는 행을 실제 본문에 우선 배분한다.
- PowerShell 7 오프라인 회귀 `126개 통과, 0개 실패`, 추적 PowerShell 파서, `git diff --check`와 직접 출력 감사를 통과했다. 실제 공급자 호출과 `resume --live`는 수행하지 않았다.

## 6. 명시적 비목표

- 원시 공급자 출력, 생성 중 토큰이나 내부 사고 과정의 실시간 중계

## 다음 구체화 순서

1. 2차 LIVE 개요·상세를 실제 사용한 뒤에도 관전감이 부족한지 확인하고 `issueKey` 미니 스레드의 필요성과 공개 계약을 판단한다.
2. 더 넓은 시각화가 필요할 때 읽기 전용 토론 흐름과 웹·데스크톱 UI를 별도 설계한다.
3. PRD 유래 장기 후보는 사용자가 우선순위를 정한 항목만 별도 PRD·구현 슬라이스로 승격한다.
4. 쓰기 또는 범위 밖 접근이 가능한 확장은 격리 게이트가 해소되기 전에는 활성화하지 않는다.
